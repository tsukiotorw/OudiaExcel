## 第3回調査（2026-07-19）

### 調査対象

- 月音旅客鉄道.oud2
- OudiaSecond GUI にて確認

### 調査目的

EkiJikoku レコードの構造および各フィールドの意味を確認する。

---

### 1. stop_flag

EkiJikoku レコード先頭の数値は停車種別を表す。

|値|意味|
|---|---|
|1|停車|
|2|通過|

GUI上で「停車」「通過」の設定と一致することを確認した。

GUIには「運行なし」の設定も存在するが、この場合は stop_flag を持たず、空レコードとなる。

例

```
1;503/504$0
2;551$1
```

---

### 2. track

`$` の後ろの値は番線番号ではなく、EkiTrack2 のインデックスである。

対応先

```
Eki.
└── EkiTrack2Cont.
    ├── EkiTrack2 (0)
    ├── EkiTrack2 (1)
    ├── EkiTrack2 (2)
    ...
```

観測結果

- 0 ～ 12 を確認
- OudiaSecond の仕様上はさらに大きな値も設定可能と思われる

よって、この値は固定範囲ではなく EkiTrack2 配列への参照インデックスと考えられる。

---

### 3. 通過レコード

通過には二種類の表現が存在する。

#### 通過時刻あり

```
2;551$1
```

意味

- stop_flag = 2
- 通過時刻 = 5:51
- track = 1

#### 通過時刻なし

```
2$1
```

意味

- stop_flag = 2
- 通過時刻なし
- track = 1

したがって、

```
2$1
```

は特殊レコードではなく、

```
2;551$1
```

から通過時刻を省略した形式である。

---

### 4. 空レコード

空レコード

```
,
```

または

```
,,,,
```

は以下の両方のケースで使用される。

- 駅を通らない
- データなし（運行なし）

GUI上では両者は区別されるが、保存形式では区別されていない。

## Operationレコード調査

### 第2回調査
実施日:
2026-07-19

対象:
月音旅客鉄道.oud2

### GUIとの対応

Operationレコードは「駅作業設定」と対応している。

駅作業設定は

- 始発駅（前作業）
- 終着駅（後作業）

の2箇所に設定できる。

### 観測例

Operation73B=3/503$/751
Operation75A=5/$0

### 確認できた事項

#### Operation73B

GUI設定

- 作業種類：出区
- 出区時刻：503
- 運用番号：751

対応関係（推定）

3 → 出区

503 → 出区時刻

751 → 運用番号

#### Operation75A

GUI設定

- 作業種類：次列車接続
- 接続種別：別列車

対応関係（推定）

5 → 次列車接続

$0 は終点時刻未設定を表している可能性がある。

### 推測

- Operationは駅作業設定を保存するレコードである。
- Bは始発駅側（前作業）を表す可能性が高い。
- Aは終着駅側（後作業）を表す可能性が高い。


## Operationレコード調査

### 第3回調査
実施日:
2026-07-19

対象:
OudiaSecond GUIによる設定変更・差分確認

### 確定事項

#### A/B の意味

- B = 始発駅（前作業）
- A = 終着駅（後作業）

#### レコード名

Operation<ID><A|B>

例

Operation73B
Operation3A

ID は Operation オブジェクトの識別子と考えられる。

---

### 作業種類

|値|GUI表示|
|---:|---|
|0|入換|
|3|出区 / 入区|
|5|前列車接続 / 次列車接続|

※ 作業種類3は、B側では「出区」、A側では「入区」となる。

---

### 出区

Operation0B=3/2359$/AAA

対応関係

3      -> 出区
2359   -> 出区時刻
AAA    -> 運用番号

---

### 入区

Operation3A=3/145$

対応関係

3     -> 入区
145   -> 入区時刻

---

### 前列車接続

Operation0B=5/$

5 -> 前列車接続

---

### 次列車接続

Operation3A=5/$0

|値|GUI表示|
|---:|---|
|0|別列車|
|1|種別変更|
|2|列車情報変更|
|3|同一列車扱い|

---

### 入換

Operation3A=0/0$555/600$0,5/$0

確認できた事項

0 -> 入換

その後の値は

入換番線
↓
入換発時刻
↓
入換着時刻
↓
空欄

を表していると考えられる。

さらに

,5/$0

が続いていることから、
Operation レコードはカンマ区切りで複数作業を保持できる。

---

### 構造に関する推測

Operation レコードは

    作業,作業,作業,...

という形式になっている可能性が高い。

各作業は

    作業種別 / パラメータ...

という可変長フォーマットを採用していると考えられる。
